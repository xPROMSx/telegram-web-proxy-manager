**Telegram Web Proxy Manager (TWPM)** مدیری رایگان برای نصب و نگهداری پروکسی اختصاصی Telegram WEB روی VPS است. موتور پروکسی [Telemt](https://github.com/telemt/telemt) است و Nginx اتصال HTTPS، مسیریابی بر اساس دامنه و نمایش سایت پوششی را فراهم می‌کند. مدیر، اجزای لازم را پیکربندی می‌کند، گواهی Let's Encrypt می‌گیرد و لینک آمادهٔ اتصال در تلگرام را نمایش می‌دهد.

**فراتر از یک نصب‌کنندهٔ Telemt:** هر نصب جدید، یک وب‌سایت اختصاصی چندصفحه‌ای با ظاهر شخصی‌سازی‌شده دریافت می‌کند. به‌جای راه‌اندازی وب‌سرور جداگانه، از Nginx موجود استفاده می‌شود و پروکسی، گواهی‌ها و سایت در قالب یک نصب مدیریت می‌شوند.

**TWPM** و [**3X-UI AUTO NGINX**](https://github.com/xPROMSx/3x-ui-auto-nginx) دو پروژهٔ xPROMSx هستند که با در نظر گرفتن سازگاری و استفادهٔ هم‌زمان توسعه می‌یابند. هر دو می‌توانند روی یک VPS از Nginx مشترک استفاده کنند و در عین حال تنظیمات، گواهی‌ها و سرویس‌های خود را مستقل نگه دارند. **TWPM با دیگر پیکربندی‌های پشتیبانی‌شدهٔ Nginx نیز کار می‌کند**؛ نصب 3X-UI اجباری نیست.

## 🚀 شروع سریع

به یک **VPS با Ubuntu 24.04 یا 26.04**، دسترسی **root**، سرویس فعال Nginx با پیکربندی SNI پشتیبانی‌شده و **دامنه یا زیردامنهٔ مستقل** نیاز دارید. رکورد DNS از نوع A باید به IPv4 عمومی VPS اشاره کند. دسترسی به TCP/80 برای دریافت گواهی HTTPS و TCP/443 برای اتصال به پروکسی ضروری است.

> [!IMPORTANT]
> دامنهٔ پروکسی تلگرام باید **آزاد و بدون استفاده** باشد. از دامنهٔ پنل 3X-UI، REALITY، Vision یا سایر سایت‌های موجود در Nginx استفاده نکنید.

**اگر 3X-UI AUTO NGINX از قبل نصب است**، منوی اصلی آن را باز کنید و گزینهٔ **4 — Telegram Web Proxy Manager** را بزنید. از این بخش می‌توانید TWPM را نصب یا نسخهٔ نصب‌شده را اجرا کنید.

**برای نصب مستقل** روی VPS دارای Nginx پشتیبانی‌شده، با دسترسی root اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/xPROMSx/telegram-web-proxy-manager/main/install.sh)
```

پس از اجرا **1 — English** یا **2 — Русский** را انتخاب کنید. رابط کاربری فقط به این دو زبان است. سپس منوی اصلی نمایش داده می‌شود (نام گزینه‌ها مطابق رابط انگلیسی آمده است):

- **1 — Install Telegram proxy:** نصب جدید یا بررسی نصب موجود بدون نصب مجدد.
- **2 — Update Telemt:** بررسی و نصب امن نسخهٔ جدید موتور پروکسی.
- **3 — Check status:** بررسی عملکرد بدون تغییر تنظیمات.
- **4 — Check and restart services:** بررسی پیکربندی، راه‌اندازی مجدد Telemt و بارگذاری دوبارهٔ تنظیمات Nginx.
- **5 — Show connection link:** نمایش دوبارهٔ لینک اتصال پروکسی به تلگرام.
- **6 — Uninstall Telegram proxy:** حذف نصب مدیریت‌شده پس از تأیید.
- **0 — Exit:** خروج.

برای اولین نصب، گزینهٔ **1 — Install Telegram proxy** را انتخاب کنید. برنامه به‌ترتیب این موارد را می‌پرسد:

1. **WEB proxy domain (دامنهٔ پروکسی).** دامنه یا زیردامنهٔ مستقل و آزادی را که از قبل آماده کرده‌اید وارد کنید.
2. **Public IPv4 (آدرس IPv4 عمومی).** مدیر تلاش می‌کند IP عمومی VPS را خودکار شناسایی کند. آن را با IPv4 سرور و رکورد DNS A دامنه مقایسه کنید. اگر درست است، فقط **Enter** بزنید. اگر شناسایی ناموفق بود یا IP اشتباه بود، آدرس صحیح را دستی وارد کنید.
3. **Use SOCKS5 upstream? [y/N] (استفاده از SOCKS5؟)** SOCKS5 یک پروکسی واسطهٔ اختیاری است که VPS می‌تواند از طریق آن به سرورهای تلگرام متصل شود. **اگر VPS مستقیماً به تلگرام دسترسی دارد، به SOCKS5 نیازی نیست؛ Enter بزنید یا N را انتخاب کنید.** اگر اتصال مستقیم ممکن نیست، *پیش از نصب* یک پروکسی SOCKS5 فعال آماده کنید؛ سپس **Y** را بزنید و آدرس میزبان و درگاه آن را وارد کنید. **نمی‌دانید SOCKS5 چیست؟ گزینهٔ N را انتخاب کنید.**

پس از نصب، مدیر HTTPS و سایت پوششی را آماده می‌کند و لینک `tg://webproxy?...` را برای افزودن پروکسی به تلگرام نمایش می‌دهد.

برای مدیریت بعدی اجرا کنید:

```bash
telegram-web-proxy-manager
```

> [!CAUTION]
> لینک اتصال تلگرام دارای کلید خصوصی دسترسی به پروکسی شماست؛ آن را منتشر نکنید یا در اختیار دیگران نگذارید.

## 🌐 سایت‌های پوششی و Nginx

**وب‌سایتی کامل به‌جای یک صفحهٔ پیش‌فرض ساده.** در نصب جدید، TWPM به‌طور خودکار یکی از سه طرح اصلی را می‌سازد:

- **Botanical Journal** — مجله‌ای دربارهٔ گیاهان.
- **Night Sky Guide** — راهنمای آسمان شب.
- **Home Kitchen** — سایتی دربارهٔ آشپزی خانگی.

هر طرح **۱۱ فایل محلی** شامل چند صفحه، سبک‌های ظاهری و تصاویر دارد. سایت با موبایل سازگار است، به منابع خارجی نیاز ندارد و ظاهری شخصی‌سازی‌شده دریافت می‌کند. طرح انتخاب‌شده در به‌روزرسانی و نگهداری حفظ می‌شود و سایت‌های نصب‌های قدیمی بدون تغییر باقی می‌مانند.

**سایت و پروکسی از همان Nginx نصب‌شده استفاده می‌کنند.** نیازی به Docker یا وب‌سرور اضافی نیست.

## 🤝 یکپارچگی با 3X-UI AUTO NGINX

**دو پروژهٔ مستقل، یک زیرساخت سازگار.** [3X-UI AUTO NGINX](https://github.com/xPROMSx/3x-ui-auto-nginx)، 3X-UI/Xray و پیکربندی مشترک Nginx را نصب و مدیریت می‌کند. **Telegram Web Proxy Manager** پروکسی مستقل Telegram WEB را با استفاده از مسیریابی پشتیبانی‌شدهٔ Nginx و دامنهٔ مخصوص خود اضافه می‌کند.

- **ترتیب پیشنهادی نصب:** ابتدا 3X-UI AUTO NGINX، سپس TWPM. پروژهٔ اول Nginx را نصب می‌کند؛ TWPM آن را نصب نمی‌کند.
- **استفادهٔ مشترک از TCP/443:** مسیریابی SNI به سرویس‌ها اجازه می‌دهد بدون جایگزین‌کردن مسیرهای 3X-UI روی یک VPS اجرا شوند.
- **نگهداری مستقل:** TWPM سرویس Telemt، سایت و گواهی‌های خود را مدیریت می‌کند و مالکیت تنظیمات یا داده‌های 3X-UI را در اختیار نمی‌گیرد.
- **سازگاری با Backup v3:** نسخهٔ فعلی 3X-UI AUTO NGINX پیکربندی‌های استاندارد TWPM را شناسایی می‌کند، اما بکاپ 3X-UI **جای بکاپ مستقل داده‌های Telemt را نمی‌گیرد**.

**سایر پیکربندی‌های Nginx نیز پشتیبانی می‌شوند**، مشروط بر اینکه با ساختارهای شناخته‌شدهٔ stream/SNI در TWPM سازگار باشند؛ از جمله بعضی ساختارها با فایل‌های `include` مستقل. برنامه پیکربندی‌های دلخواه و ناشناخته را بازسازی نمی‌کند و در صورت ناسازگاری یا تداخل، با حفظ ایمنی از نصب خودداری می‌کند. [نیازمندی‌های فنی](docs/OPERATIONS.md#nginx-requirements).

> [!IMPORTANT]
> TWPM فقط از **Ubuntu 24.04 و 26.04** پشتیبانی می‌کند. پشتیبانی از Debian در 3X-UI AUTO NGINX به معنی پشتیبانی Telegram Web Proxy Manager از Debian نیست.

## 🔄 به‌روزرسانی و نگهداری

در نصب اولیه، مدیر نسخهٔ تأییدشده‌ای از Telemt را راه‌اندازی می‌کند. **Universal Update** به‌طور مستقل جدیدترین نسخهٔ رسمی پایدار و سازگار را پیدا کرده و پیش از جایگزینی بررسی می‌کند. در صورت شکست به‌روزرسانی، امکان بازگشت به نسخهٔ سالم قبلی با حفظ وضعیت فراهم است.

به‌روزرسانی **خود TWPM** و **Telemt** دو عملیات جداگانه‌اند. نگهداری معمول سایت را از نو نمی‌سازد، اطلاعات محرمانه را بازنشانی نمی‌کند و بدون موافقت، نصب‌های قدیمی را به ساختار جدید منتقل نمی‌کند.

بررسی وضعیت از منو در دسترس است و برای نصب‌های پشتیبانی‌شده امکان تعمیر وجود دارد. حذف فقط روی مواردی انجام می‌شود که مالکیت آن‌ها به مدیر تعلق دارد؛ حذف گواهی‌ها نیازمند تأیید جداگانه است.

## ⚙️ پیش‌نیازها و آزمون‌ها

- **سیستم‌عامل:** Ubuntu 24.04 / 26.04، معماری x86_64 یا ARM64، دسترسی root و systemd.
- **شبکه:** دامنه یا زیردامنهٔ مستقل، رکورد DNS A صحیح و دسترسی به درگاه‌های TCP لازم.
- **Nginx:** پیکربندی موجود و پشتیبانی‌شدهٔ stream/SNI. مدیر Nginx، 3X-UI یا Xray را نصب نمی‌کند و قوانین فایروال سیستم را تغییر نمی‌دهد.
- **Telemt:** توسط TWPM نصب می‌شود. نسخهٔ پایهٔ تأییدشده برای نصب جدید **3.5.16** است و Universal Update جداگانه عمل می‌کند.

پروژه روی نسخه‌های پشتیبانی‌شدهٔ Ubuntu آزمون‌های خودکار و یکپارچه‌سازی، از جمله آزمایش‌های واقعی Nginx و Telemt، دارد. پیکربندی‌های غیرمعمول Nginx به بررسی سازگاری جداگانه نیاز دارند. [پوشش و محدودیت آزمون‌ها](docs/CI-COVERAGE.md).
